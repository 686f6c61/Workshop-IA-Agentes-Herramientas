# Licencias de uso

Antes de hablar de siglas, la intención es sencilla: quiero que este facsímil se pueda leer,
compartir, estudiar, adaptar y llevar a clase o a un proyecto real sin pedir permiso cada vez.
Pero también quiero que se conserve la trazabilidad. Si una explicación, un diagrama o un kit te
sirven, úsalo; solo no borres de dónde viene ni confundas material propio con material de terceros.

Por eso esta página separa dos cosas que suelen mezclarse demasiado rápido: **el contenido educativo**
y **los artefactos ejecutables**. No se reutilizan igual unas notas docentes que un script de Python,
un dataset de ejemplo o una plantilla de evaluación.

## Por qué hay dos licencias

Este facsímil contiene texto, figuras, diagramas, tablas, mapas, referencias, explicaciones y notas
editoriales. Esa parte se parece más a un material docente abierto que a un paquete de software.
También contiene código, scripts, plantillas, notebooks, kits descargables y pequeños proyectos que
una persona puede ejecutar para practicar. Esa parte sí se parece a software.

Si usara solo MIT para todo, el código quedaría bien cubierto, pero el texto educativo quedaría explicado
de una forma poco natural. Si usara solo Creative Commons para todo, el contenido docente quedaría claro,
pero el código no estaría bajo la licencia que la mayoría de equipos de ingeniería esperan encontrar en
un ejemplo reutilizable. La solución más limpia es separar ambas capas.

En la práctica significa que puedes copiar, redistribuir, traducir, adaptar, resumir, ampliar o usar

cambios, dilo. No hace falta solemnizarlo, pero sí dejar claro qué viene de aquí y qué has modificado.

Puedes, por ejemplo:

- usar una explicación en tus apuntes de clase;
- adaptar un diagrama para una presentación interna;
- traducir una sección para un curso;
- citar un fragmento en un TFG, TFM, artículo o documentación profesional;
- construir una versión propia de un capítulo siempre que mantengas la atribución.

Una atribución sencilla puede ser:

Si quieres ser más preciso, añade también la URL de la página concreta y la fecha en la que la consultaste.
Eso ayuda mucho en trabajos académicos, documentación de empresa y materiales que puedan cambiar con el
tiempo.

## Qué no queda cubierto automáticamente

Las licencias anteriores cubren el material propio del facsímil. No convierten en libre aquello que ya
pertenece a otra persona u organización. Esto es importante en IA porque casi todo se apoya en capas:
papers, documentación de proveedores, APIs, modelos, pesos, datasets, librerías, imágenes, benchmarks y
repositorios externos.

Si un capítulo cita un artículo, el artículo conserva su propia licencia. Si un laboratorio usa un dataset
público, debes mirar la licencia del dataset. Si una práctica llama a una API comercial, debes revisar los
términos del proveedor. Si un ejemplo menciona un modelo, sus pesos, su card o su runtime pueden tener
condiciones distintas.

Esta página tampoco te da permiso sobre marcas registradas, nombres de productos, capturas externas,
modelos de terceros, datasets ajenos, documentación enlazada o recursos que ya tengan su propio marco legal.
La atribución al facsímil no sustituye la atribución ni las condiciones del recurso original.

## Cómo usar este material con buen criterio

Puedes usar este facsímil para estudiar, enseñar, preparar clases, citar en trabajos, construir apuntes,
crear materiales derivados, adaptar prácticas o incorporar fragmentos a documentación interna. Ese es
precisamente el objetivo: que no sea un texto muerto, sino una base que puedas llevar a tu contexto.

Lo razonable es hacer tres cosas:

1. Cita la obra cuando reutilices texto, figuras o explicaciones.
2. Conserva la licencia MIT cuando reutilices código o kits de forma sustancial.
3. Revisa las licencias externas cuando el capítulo use datos, modelos, herramientas o servicios de terceros.

No hace falta complicarlo más. La idea no es poner barreras; es evitar que el material pierda origen,
contexto y responsabilidad por el camino.
